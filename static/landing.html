webhook-inbox

Receives webhooks from Midtrans, Xendit, GitHub or any HMAC signer, checks the signature, stores every delivery in Postgres and forwards it with retries.

Things to try

  • Open a midtrans delivery. Its billing target fails twice and works on the third try, and the timeline shows the backoff between tries.
  • Press Replay to all targets there and watch the new tries arrive on the same page.
  • Open Dead letters. Those deliveries used all 5 tries against a target that is always down.
  • POST anything to /in/github without a valid signature. You get a 401, and it shows up in the list as rejected.

Send a signed webhook

Paste this into a terminal with curl and openssl, then look for it in the inbox.

body='{"action":"opened","repository":{"full_name":"kabut-labs/billing-api"}}'
sig=$(printf %s "$body" | openssl dgst -sha256 -hmac demo-github-secret | sed 's/^.* //')
curl -i https://webhook-inbox-zeta.vercel.app/in/github \
  -H "x-hub-signature-256: sha256=$sig" \
  -H "x-github-delivery: try-$RANDOM$RANDOM" \
  -d "$body"

Change one character of the body after signing and it gets a 401. From a clone of the repo, BASE=https://webhook-inbox-zeta.vercel.app examples/send.sh midtrans sends one that goes through the failing target, and partner sends one that ends up in the dead letters. Both use the same demo secrets, which protect nothing but this page.

About this demo

  • Everything here is made up. The password and signing secrets are public, so whatever you send can be read by anyone. Please don't send real data. What visitors add is deleted after about 6 hours, the next time the app starts.
  • Forwarding only goes to a small test target in the same container, and it can't be pointed anywhere else.
  • It runs in a free container that starts on the first request and stops about 30 seconds after the last one. The retry worker stops with it, so a retry due later than that waits for the next request, which starts the app and picks it up. A normal install keeps running and retries on time.
